# Anomaly Review Studio

Anomaly Review Studio is a lightweight Streamlit portfolio project that profiles CSV data, flags data quality issues, and generates review-ready rules and documentation. The app uses a polished dashboard layout with summary cards, review priorities, charts, and a structured report flow that reads well in a portfolio demo.

## What it does

- Upload a CSV or load the bundled demo dataset
- Profile columns for missing values, uniqueness, and basic distribution signals
- Generate human-readable data quality rules
- Flag rule violations and summarize anomalies
- Track durable issue lifecycle (`new`, `acknowledged`, `resolved`) in an Issue Queue
- Compare each run against the latest baseline run for the same source
- Evaluate quality gates (warn-only by default)
- Apply context-aware severity and remediation guidance per finding
- Export a structured JSON report, Markdown narrative, and PDF summary
- Present a concise summary with review priorities and a clean tabbed dashboard

## Project structure

- `app.py` - Streamlit entrypoint
- `src/anomaly_review_studio/` - reusable profiling, rules, reporting, and I/O code
- `tests/` - unit tests for deterministic logic
- `data/demo_anomaly_review.csv` - demo dataset with intentional data issues

## Setup

1. Create and activate a Python virtual environment.
2. Install dependencies:

```bash
pip install -r requirements.txt
```

## Optional Supabase setup (for deployed persistence)

Set:

- `SUPABASE_URL`
- `SUPABASE_KEY`

Create tables in Supabase SQL editor:

```sql
create table if not exists runs (
  run_id text primary key,
  source_label text not null,
  rows int not null,
  columns int not null,
  missing_cells int not null,
  total_violations int not null,
  quality_score numeric not null,
  baseline_run_id text,
  baseline_summary jsonb default '{}'::jsonb,
  workflow_config jsonb default '{}'::jsonb,
  created_at timestamptz default now()
);

create table if not exists findings (
  finding_id text primary key,
  run_id text not null,
  source_label text not null,
  column text not null,
  rule_type text not null,
  description text,
  base_severity text,
  effective_severity text,
  column_role text,
  violations int default 0,
  pass_rate_pct numeric,
  expected_value text,
  min_value numeric,
  max_value numeric,
  guidance jsonb default '{}'::jsonb,
  status text default 'new',
  owner text default '',
  notes text default '',
  baseline_delta text default 'unchanged',
  updated_at timestamptz default now()
);

create table if not exists finding_status_events (
  id bigint generated by default as identity primary key,
  finding_id text not null,
  source_label text not null,
  status text not null,
  owner text,
  notes text,
  event_at timestamptz default now()
);

create table if not exists gate_results (
  id bigint generated by default as identity primary key,
  run_id text not null,
  source_label text not null,
  status text not null,
  gate_summary jsonb not null,
  created_at timestamptz default now()
);
```

## Demo workflow

1. Open the app.
2. Click **Load demo dataset** or upload a CSV.
3. Review the summary cards, column profile, suggested rules, and narrative report.
4. Use the tabs to switch between overview, columns, rules, issue queue, trends, and report views.
5. Download the JSON, Markdown, or PDF output.

## How to use (step-by-step)

1. Start the app locally:

```bash
python -m venv .venv
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
# macOS / Linux
# source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

2. In the left sidebar, either click **Load demo dataset** to open the bundled sample or upload your CSV using **Upload CSV**.
3. Optionally provide a comma-separated list of `Required columns` (e.g., `customer_id, age`) to enforce column-presence checks only.
4. Review the **Summary** section at the top for quick, actionable recommendations.
5. Use the **Overview** tab to inspect KPI cards and charts, the **Columns** tab for per-column metrics, the **Rules** tab for suggested quality rules and rule explanations, and the **Report** tab to read the full narrative.
6. Export the results with the Download buttons: JSON (machine-readable rules), Markdown (human-readable report), or PDF (presentation-ready summary).

## Quick tips for demos

- Use the bundled `data/demo_anomaly_review.csv` to demonstrate the end-to-end flow without external dependencies.
- Emphasize the summary and top recommendations when walking interviewers through the app.
- Optional model-powered explanation enrichment can be added later; deterministic rule generation works without any external API.

## Example outputs

The app will surface issues such as:

- Missing values in required columns
- Duplicate identifiers
- Invalid postal codes
- Unexpected category values
- Extreme numeric values relative to the observed data

## Data dictionary behavior

The app creates a simple data dictionary from profiling results. If an API key is available, the LLM adapter can be extended to rewrite the default explanations; otherwise the project stays fully offline and uses deterministic text.
